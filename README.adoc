= OpenShift 103 Workshop

The source of the OpenShift 103 Workshop site, for platform engineers who run Amazon EKS or Azure AKS and now operate managed OpenShift: Red Hat OpenShift Service on AWS (ROSA) and Azure Red Hat OpenShift (ARO).

The site is https://redhat-na-ssa.github.io/openshift-103-workshop/[redhat-na-ssa.github.io/openshift-103-workshop].
Its https://redhat-na-ssa.github.io/openshift-103-workshop/instructor.html[Workshop Instructor Guide] page is the facilitator guide: the environment, before the day, the agenda and timings, and delivery notes.

This README is for maintainers of the repo.

== Layout

The repo is one Antora component made of a home part and nested workshops:

[cols="1,3",options="header"]
|===
|Folder |What it holds

|`content/`
|The home part: the Workshop Home, Workshop Instructor Guide and Workshop Attendee Guide pages, and the site's title, navigation and attributes in `content/antora.yml`.

|`workshops/rosa-and-aro/`
|The OpenShift on ROSA and ARO workshop: its pages in `modules/rosa-and-aro/pages`, its diagrams in `modules/rosa-and-aro/assets/images`, and its navigation in `modules/rosa-and-aro/partials/nav-items.adoc`.
Its own `antora.yml` is used only when it is built alone.

|`sample-app/`
|The sample application that runs through Modules 2 to 4, and its `Containerfile`.

|`exercises/`
|Files the exercises use from the repo on GitHub, such as the application Argo CD syncs in Module 1.
|===

The site's look (theme, CSS, tabs, copy buttons, footer), the PDF look and the build and PDF workflows come from https://github.com/shpwrck/workshop-common[workshop-common], which the other OpenShift workshops share; change them there.

== Preview

Clone https://github.com/shpwrck/workshop-common[workshop-common] next to this repository, and run this from this repository's folder to preview the whole site:

[source,bash]
----
../workshop-common/scripts/preview.sh --watch
----

It builds the site the way the Pages workflow does, serves it on http://localhost:8080/ and rebuilds it when you save a change.
It needs Node.js and Python 3.

To build one workshop on its own, as it must build before it joins the site:

[source,bash]
----
../workshop-common/scripts/preview.sh --watch --workshop rosa-and-aro
----

Every pull request runs *Check content*, which holds the lines it changes to the formatting conventions and checks that the site, and each workshop on its own, builds without warnings or broken links, and *Test PDF Build*.
A merge to `main` publishes the site.

== Adding a Workshop

Run this from this repository's folder, with a short lowercase name and the workshop's title:

[source,bash]
----
../workshop-common/scripts/add-workshop.py NAME "Workshop Title"
----

It creates `workshops/NAME` from the workshop template and lists it in both playbooks, the home part's navigation, and the home, instructor and attendee pages.
Then write its pages, its setup requirements, and its row on the instructor page.

== Sample App Image

The *Sample App Image* workflow builds the sample application from `sample-app/Containerfile` on every push to `main` that changes `sample-app/`, and pushes two images to `ghcr.io/redhat-na-ssa/openshift-103-workshop/sample-app`: `1.0`, which runs under any user ID, and `1.0-root`, which Module 2 uses to show a failing root image.
Pull requests only build them.
Run the workflow from the Actions tab to rebuild the images without a change.
`sample-app/README.md` describes the application.

== Releases

Run the *Release* workflow from the Actions tab with the next version, such as `v1.1.0`, or push a tag of that name.
It publishes the PDF, the runtime and tools images, the Helm chart and an offline bundle; see "Releases" in workshop-common's README.
To ship another file with every release, put it in `downloads/`.
The tools image adds `rosa`, `aws` and `az` (`tools/install.sh`) to the shared tools.
