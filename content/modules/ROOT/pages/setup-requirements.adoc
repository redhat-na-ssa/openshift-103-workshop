= Setup Requirements
:hardbreaks-option:

This page lists everything needed to run this workshop on each of the four platforms it compares: Amazon EKS, Azure AKS, Red Hat OpenShift Service on AWS (ROSA) and Azure Red Hat OpenShift (ARO).

Module 2 has attendees create clusters, so attendees need their own cloud accounts, or a sandbox account per attendee or pair.
If the instructor provisions the clusters ahead of time instead, attendees need only the binaries and the cluster access described below, and Module 2 becomes a walkthrough.

== Cloud Accounts and Quotas

[cols="1,3",options="header"]
|===
|Platform |Requirement

|EKS
|An AWS account, in a region where EKS is available.
Service Quotas must allow at least 16 On-Demand standard vCPUs for the node groups.

|ROSA
a|The same AWS account, with the ROSA service enabled in the AWS console and linked to a Red Hat account at https://console.redhat.com[console.redhat.com].
The Elastic Load Balancing service-linked role must exist, and Service Quotas must cover a ROSA cluster.
Check the quotas with:

[source,bash]
----
rosa verify quota
----

|AKS
|An Azure subscription, with quota for at least 16 vCPUs in the chosen region.

|ARO
a|The same Azure subscription, with quota for at least 40 vCPUs in the region (3 control plane nodes on Standard_D8s_v5 and 3 workers on Standard_D4s_v5).
A Red Hat pull secret is optional; it adds access to Red Hat Operators.

These resource providers must be registered:

[source,bash]
----
az provider register --namespace Microsoft.RedHatOpenShift --wait
az provider register --namespace Microsoft.Compute --wait
az provider register --namespace Microsoft.Storage --wait
az provider register --namespace Microsoft.Authorization --wait
az provider register --namespace Microsoft.Network --wait
----
|===

== Binaries

Each attendee needs these command line tools on their workstation or in the workshop terminal.

[cols="1,1,2",options="header"]
|===
|Tool |Used for |Notes

|EKS and AKS
|Within one minor version of the cluster.

|`oc`
|ROSA and ARO
|Matches the OpenShift version.
Can also replace kubectl on EKS and AKS.

|`aws` (v2)
|EKS and ROSA
|Configured with credentials for the attendee's AWS account.

|`eksctl`
|EKS
|Creates the EKS cluster and its node groups.

|`rosa`
|ROSA
|Logged in with a token from console.redhat.com.

|`az`
|AKS and ARO

|`helm`
|EKS and AKS

|All

== Roles and Permissions

[cols="1,3",options="header"]
|===
|Platform |Who needs what

|EKS
a|The attendee's AWS identity needs permission to create EKS clusters with eksctl:

* EKS
* EC2
* CloudFormation
* IAM role and OIDC provider creation
* Auto Scaling

The `AdministratorAccess` policy on a sandbox account is the simplest choice.

|ROSA
a|The attendee's AWS identity needs the same IAM rights, to create the ROSA account-wide roles, the OIDC configuration and the operator roles:

[source,bash]
----
rosa create account-roles --mode auto
rosa create oidc-config --mode auto
rosa create operator-roles --mode auto --prefix <prefix> --oidc-config-id <oidc-config-id>
----

Their Red Hat account needs permission to create clusters in the organization.

|AKS
|`Contributor` on the subscription or on a dedicated resource group, plus `User Access Administrator` to assign roles to managed identities for Workload ID.

|ARO
|`Contributor` and `User Access Administrator` on the subscription.
In Microsoft Entra ID, the attendee must be able to create app registrations and service principals, because creating an ARO cluster also creates its service principal.
|===

== Cluster Components and Operators

[cols="1,3",options="header"]
|===
|Platform |What must be installed or enabled

|EKS
|Amazon EBS CSI driver add-on (persistent storage), AWS Load Balancer Controller (ingress, Module 4), metrics-server (autoscaling, Module 5) and Cluster Autoscaler or Karpenter (node scaling, Module 5).
An IAM OIDC provider for the cluster (IRSA, Module 3).

|AKS
a|Create the cluster with Workload ID (Module 3), the cluster autoscaler (Module 5) and the application routing add-on (ingress, Module 4) enabled:

[source,bash]
----
az aks create --resource-group <resource-group> --name <cluster-name> \
  --enable-oidc-issuer \
  --enable-workload-identity \
  --enable-cluster-autoscaler --min-count 1 --max-count 3 \
  --enable-app-routing
----

Azure Disk CSI and metrics-server are installed by default.

|ROSA
|Nothing beyond the defaults: the ingress controller, OVN-Kubernetes, the EBS CSI driver and cluster monitoring come with every cluster.
Create the cluster in STS mode (the default) for Module 3.

|ARO
|Nothing beyond the defaults: the ingress controller, OVN-Kubernetes, the Azure Disk CSI driver and cluster monitoring come with every cluster.
|===

== Access

Attendees log in to EKS with their AWS identity; EKS creates an access entry for the cluster creator.

[source,bash]
----
aws eks update-kubeconfig --region <region> --name <cluster-name>
----

Attendees log in to AKS with:

[source,bash]
----
az aks get-credentials --resource-group <resource-group> --name <cluster-name>
----

Attendees log in to ROSA as cluster-admin, through an identity provider or a temporary admin user:

[source,bash]
----
rosa create admin --cluster <cluster-name>
----

Attendees log in to ARO as the kubeadmin user, with the password from:

[source,bash]
----
az aro list-credentials --resource-group <resource-group> --name <cluster-name>
----

Module 3 then adds an identity provider on each cluster.

Workstations need outbound HTTPS to:

* the AWS and Azure APIs
* console.redhat.com
* api.openshift.com
* quay.io
* registry.redhat.io

== Cost and Cleanup

Each cluster costs money while it runs; ROSA and ARO clusters cost the most.
Delete every cluster at the end of the workshop:

[source,bash]
----
eksctl delete cluster --name <cluster-name> --region <region>
az aks delete --resource-group <resource-group> --name <cluster-name> --yes
rosa delete cluster --cluster <cluster-name> --yes
az aro delete --resource-group <resource-group> --name <cluster-name> --yes
----

After the ROSA cluster is deleted, remove its operator roles and OIDC configuration:

[source,bash]
----
rosa delete operator-roles --prefix <prefix> --mode auto
rosa delete oidc-config --oidc-config-id <oidc-config-id> --mode auto
----
