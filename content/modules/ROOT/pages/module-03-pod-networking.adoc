= Pod Networking and Policy

NOTE: This section is an outline. Its diagrams and exercises are being written and validated on ROSA and ARO.

With the Amazon VPC CNI and Azure CNI, pods get addresses from your VPC or virtual network.
ROSA and ARO run OVN-Kubernetes as an overlay: pod addresses never appear in the VPC or virtual network, and traffic leaves the cluster from the node's address unless you assign an egress IP.
This section explains the packet path, then applies network policy at two levels: per project, and cluster-wide.

== On EKS and AKS

* EKS: pods take VPC addresses, can carry their own security groups, and you plan subnets around address exhaustion. Network policy is a VPC CNI feature you turn on.
* AKS: choose Azure CNI, Azure CNI overlay, or Azure CNI powered by Cilium, and a network policy engine.
* Private clusters: the EKS endpoint can switch between public and private at any time, and AKS offers private clusters and API server VNet integration.

== On ROSA and ARO

Outline of the exercise:

. Compare a pod's address with the node and VPC or virtual network addresses.
. Apply a default-deny NetworkPolicy in the sample application's project, and allow only the router.
. Apply an AdminNetworkPolicy that blocks every project from a sensitive namespace.
. Show that a project administrator cannot override it.
. Check the source address of traffic leaving the cluster.

== What Matters

* OVN-Kubernetes is the only network plugin. There is no CNI choice.
* NetworkPolicy works with nothing to enable. AdminNetworkPolicy adds cluster-wide rules that project administrators cannot override.
* Egress IPs give a project a fixed source address, with cloud-specific limits: on AWS the capacity depends on the instance type, and on ARO namespace egress IPs need user-defined routing.
* Private clusters are an install-time choice on ROSA and ARO. ROSA HCP workers always reach the hosted control plane over AWS PrivateLink.

== Where Each Wins

[cols="1,1",options="header"]
|===
|ROSA and ARO win |EKS and AKS win

|No pod address planning in your VPC or virtual network.
|Pods are first-class network citizens: routable addresses, security groups for pods, flow logs by pod address.

|NetworkPolicy, AdminNetworkPolicy and egress IPs built in.
|Cilium on AKS adds eBPF dataplane, L7 and FQDN policy.

|A supported private pattern that keeps SRE access working.
|Endpoint visibility can change after the cluster is created.
|===
