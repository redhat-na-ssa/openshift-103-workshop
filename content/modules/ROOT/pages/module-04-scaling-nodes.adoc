= Scaling Nodes

NOTE: This section is an outline. Its diagrams and exercises are being written and validated on ROSA and ARO.

EKS Auto Mode, Karpenter and AKS node auto-provisioning pick an instance type for each batch of pending pods, mix spot and on-demand capacity, and consolidate nodes.
ROSA and ARO scale in groups of identical nodes: machine pools on ROSA, MachineSets on ARO, with the cluster autoscaler.
ROSA HCP also offers the Red Hat build of Karpenter from OpenShift 4.22.
This is an area where the native services are ahead, and this section says so.

== On EKS and AKS

* EKS: managed node groups with the Cluster Autoscaler, or Karpenter, or EKS Auto Mode, which also patches and replaces nodes.
* AKS: node pools with the cluster autoscaler, or node auto-provisioning, which is based on Karpenter.
* You own node images, unless Auto Mode or AKS node OS auto-upgrade does it for you.

== On ROSA and ARO

Outline of the exercise:

. ROSA: create an autoscaling machine pool with the `rosa` CLI.
. ARO: copy a MachineSet and add a MachineAutoscaler with `oc`.
. Scale the sample application past the cluster's capacity, and watch new nodes join. Read the next part while they start.
. Look at how the node OS is updated, and who does it.

== What Matters

* ROSA and ARO use different tools: ROSA machine pools are managed through the `rosa` CLI or OpenShift Cluster Manager, while standard ARO has no pool API and you edit MachineSets in the cluster.
* Each machine pool or MachineSet uses one instance type.
* ROSA machine pools can scale to zero.
* The Red Hat build of Karpenter requires ROSA HCP on 4.22. ARO hosted control planes autoscaling is in preview.
* Red Hat owns the node OS image and its patching on ROSA and ARO.

== Where Each Wins

[cols="1,1",options="header"]
|===
|ROSA and ARO win |EKS and AKS win

|No node images to build or roll: Red Hat patches the OS.
|Karpenter, Auto Mode and node auto-provisioning are mature, flexible and bin-pack well.

|The same machine pool model across both clouds.
|Spot and mixed instance types per workload without extra pools.
|===
